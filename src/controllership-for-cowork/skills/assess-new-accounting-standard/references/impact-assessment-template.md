# Impact assessment template

## Effective-date worksheet

| Field | Value |
|---|---|
| Pronouncement | Issuer, number, title, issue date |
| Amendments or deferrals since issue | Number and effect on dates |
| Effective-date wording (retrieved) | Short quotation with paragraph reference |
| Entity type used | Public business entity, SEC filer category, other; or IFRS jurisdiction |
| Endorsement or adoption status (IFRS) | Endorsed / Not yet endorsed / Not required, with source |
| Fiscal year start | From the Finance Profile |
| First annual period | Computed |
| First interim period | Computed (where interim application differs, show both) |
| Date of initial application | Computed |
| Earliest comparative period start | Computed from the number of comparative periods presented |
| Early adoption | Permitted / Not permitted; conditions |

Compute the dates in code from the fiscal calendar. Phrases differ: "beginning after 15 December 2026" excludes a period beginning on 15 December 2026; "beginning on or after 1 January 2027" includes 1 January 2027.

## Dimension checklists

### Accounting policies
- Which policy manual sections describe current practice (cite section and version)?
- Which elections or practical expedients does the new guidance add, remove or change?
- Does any policy reference superseded paragraphs?

### Contracts and arrangements
- Which contract types contain terms the guidance targets (search the repository by clause keywords and counterparty type)?
- How many contracts, and what share of the related balance, do they represent (count and value computed in code)?
- Are standard templates affected for future contracts?

### Systems and data
- Which ledgers, subledgers, consolidation and reporting tools hold the affected data?
- Are new accounts, attributes, dimensions or mappings needed?
- Is historical data available at the granularity required for comparatives?
- Which reports, interfaces and spreadsheets used in reporting are affected?

### Processes
- Which close, reporting, forecasting and contract-approval processes change?
- Which teams outside Finance (sales, procurement, treasury, legal, investor relations) are affected?

### Controls
- Which existing controls in the risk and control matrix address the affected accounts and disclosures (control ID and name)?
- Which controls need redesign, and where are new controls needed (route design to the Internal Controls plugin)?
- Is new information produced by the entity used in a control, needing completeness and accuracy evidence?

### Disclosures
- New, changed and removed disclosures, with citations.
- Transition disclosures for the change in accounting principle or policy.
- Pre-adoption disclosures in reports issued before the effective date.
- Interim reporting requirements in the year of adoption.
- Non-GAAP or alternative performance measures, KPIs and covenant definitions that reference affected lines.

## Rating rules

| Rating | Use when |
|---|---|
| Affected | The requirement applies and evidence (document, data) shows the entity has the item |
| Possibly affected - confirm | Indicators exist but a fact or judgement is needed; name the question and owner |
| Not affected | The entity has no such item; reason and evidence stated |
| Not assessed - information missing | The source needed was not available; name it |

## Quantification labels

| Label | Use when |
|---|---|
| Computed - data supplied | Calculated from complete actual data for the period |
| Estimated - proxy data | Calculated from partial periods, samples or proxies; describe the proxy and extrapolation |
| Not quantified - data unavailable | No data; state what is needed |

## Implementation plan back-scheduling

Work backward from the first reporting date (first interim or annual filing that applies the guidance):

| Milestone | Default offset (adjust to the user's calendar) |
|---|---|
| Disclosure drafts reviewed by auditor | Before the first reporting date's audit or review fieldwork |
| Dry run or parallel close completed | At least one quarter before the first reporting period end |
| Controls designed and documented | Before the dry run |
| Systems configured and tested | Before the dry run |
| Comparative data captured and remapped | Before the dry run when comparatives are restated |
| Policy approved | Before system configuration |
| Elections decided | Before policy approval |
| Pre-adoption disclosure | Every report issued between issue date and adoption |

Offsets are defaults for structuring the plan; actual dates come from the user or the close calendar. Status values: Not started, In progress, Complete, At risk, Blocked.
